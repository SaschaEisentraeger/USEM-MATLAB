\chapter{Known issues and fixed bugs}
\label{ch:issues}

Tests that document an open bug get the tag \code{KnownIssue}. They are excluded
from the default run and fail until the bug is fixed
(\code{run_tests('KnownIssues', true)} includes them). There are currently no
open \code{KnownIssue} tests: the bugs found while writing the test suite are
fixed (\cref{sec:fixed}).

\section{Remaining limitations}

\begin{itemize}
  \item \textbf{Default route of the dynamic analysis.} With
    \code{flag_mRHS = true}, \code{Solver_Transient} ignores the method code and
    runs the central difference method (codes below 300) or HHT-$\alpha$ (300 and
    above), see \cref{sec:dynamic}.
  \item \textbf{ABAQUS readers} expect the structure written by ABAQUS/CAE:
    boundary-condition data lines must contain \code{Set}; sets must be defined in
    the assembly; node labels must be consecutive from 1; in 8-node meshes the
    corner nodes must be numbered first. Violations of the last three raise errors
    instead of producing wrong data or endless loops (\cref{ch:input}).
  \item \textbf{Modal and frequency-domain analyses} only honour homogeneous
    Dirichlet conditions; the frequency-domain analysis ignores damping.
  \item \code{CentralDifferenceMethod_te}, \code{Solver_Transient_symrcm} and the
    second variants of the Padé integrators (\code{PadeTimeIntegrator2},
    \code{PadeTimeIntegrator_ND2}) are not called by the program and not tested.
  \item \code{ShapeFunctions2D_Metric_Tria} (triangles) is unfinished ($p\le2$) and
    not used.
  \item The result workspaces that came with the code
    (\code{subroutines/Results/Static}, not under version control) were partly
    created with an earlier version of the load routines (opposite load sign in
    the quadratic Lee \& Bathe cases). The regression tests therefore use the
    analytical solution (\code{LeeBathePatchTest}).
  \item \textbf{Unsymmetric matrices in dynamics.} Eigenvalues can be complex and
    energy is not conserved, see \cref{sec:unsymmetric}.
\end{itemize}

\code{MirbagheriMethod} (104) converges with first order. This is by design, not
a bug: the factor $\eta = 1.025$ on the acceleration term of the Noh--Bathe
predictor adds dissipation against spurious oscillations, and any $\eta \ne 1$
makes the scheme first-order accurate.
